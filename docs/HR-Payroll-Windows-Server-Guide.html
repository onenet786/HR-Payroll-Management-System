What gets installed

Everything comes from one package (HRPayroll-Windows-Setup-<version>.zip). The server needs no internet access to install and nothing else has to be installed first.

PartWhat it isWhere
HR Payroll Database (service HRPayrollDB)Built-in PostgreSQL 16 database engine. Listens only on this server (localhost), port 5433. Pre-tuned for an HR system (about 256 MB memory).C:\HRPayroll\runtime\pgsql, data in C:\HRPayrollData\pgdata
HR Payroll Application (service HRPayrollApp)The HR & Payroll web application (Node.js). Starts after the database, restarts by itself if it stops.C:\HRPayroll\app\<version>
HR Payroll Nightly Backup (scheduled task)Encrypted database backup every night, 14 kept, optional copy to a network share.C:\HRPayrollData\backups
Firewall rule "HR Payroll Application"Opens the application port for Domain and Private networks only.Windows Defender Firewall
ToolsStatus, backup, restore, update, uninstall scripts.C:\HRPayroll\tools

Both services run as the built-in NETWORK SERVICE account, not as an administrator. The settings folder (C:\HRPayroll\config) is readable only by Administrators, SYSTEM and the service.

Installing

  1. Copy HRPayroll-Windows-Setup-<version>.zip to the server and extract the whole zip, e.g. to C:\Setup\HRPayroll.
  2. Right-click Setup.cmd → Run as administrator.
  3. Answer the questions: company name, administrator email and name, edition (full with FBR/EOBI/PF/gratuity, or lite for a small business) and, if you have one, the address users will open.
  4. Choose the drives. Setup lists the server's disks with their free space and asks for the program folder (default C:\HRPayroll, about 250 MB: application, database engine, settings) and the data folder (database, documents, backups, logs; it grows over time). For the data folder it suggests the non-system disk with the most free space, e.g. D:\HRPayrollData. Press Enter to accept, type another folder, or type just a drive letter (e.g. D) to use the suggested folder name on that drive. Only local fixed disks are accepted (no network drives, USB sticks or drive roots).
  5. Setup shows a summary (company, administrator, program and data folders). Type Y to install or N to stop without changing anything.
  6. Setup checks the server (rights, free ports, disk), copies the files, creates the built-in database, the tables and the first administrator, starts both services, opens the firewall port, schedules the nightly backup and checks that the application answers. It takes about 5 minutes.
  7. At the end it shows the address, the administrator email and, if you did not choose one, a generated password (shown once). A summary without the password is saved in C:\HRPayroll\config\install-summary.txt.
Keep a copy of the settings file off the serverC:\HRPayroll\config\.env holds BACKUP_ENCRYPTION_KEY. Without it no backup can be restored. Copy the file to a safe place (password manager, encrypted USB stick in a safe) right after installation.

First sign-in and next steps

  1. Open the address from the summary and sign in. Change the password (top right → profile) and switch on two-step verification.
  2. Company Setup: company details, branches, departments, designations, shifts and the attendance policy.
  3. Coming from CyberAP: menu Data Import → Create package from SQL Server (next sections and the CyberAP Data Migration Guide).
  4. Kiosks: install the attendance kiosk on each branch PC and register it with a kiosk setup code (Kiosk devices → Setup codes). The code contains this server's address.
  5. Mobile app: needs HTTPS and a reachable address. Employees enter your address (e.g. hr.company.com) on the app's first screen.

HTTPS

The application serves HTTPS itself; no IIS or other web server is needed. A renewed certificate file is picked up automatically, without a restart.

Option 1 — Free Let's Encrypt certificate (recommended)

You need a domain you own (e.g. company.com). Create the name hr.company.com in your internal DNS pointing to the server's IP (and, only if you publish it, in public DNS too). Let's Encrypt checks ownership through a DNS record, so the server does not have to be reachable from the internet.

  1. Download win-acme (wacs.exe, from win-acme.com) to C:\Tools\win-acme.
  2. Run, as Administrator, with your DNS provider's plug-in (Cloudflare, Azure DNS, Route 53…) or manual DNS validation:
wacs.exe --source manual --host hr.company.com --validation cloudflare --cloudflareapitoken <token> ^
  --store pemfiles --pemfilespath C:\HRPayroll\certs
  1. win-acme writes hr.company.com-chain.pem and hr.company.com-key.pem to C:\HRPayroll\certs and creates its own scheduled task that renews them every ~60 days.
  2. Grant the service read access: icacls C:\HRPayroll\certs /grant "NT AUTHORITY\NETWORK SERVICE":(OI)(CI)R
  3. Add to C:\HRPayroll\config\.env (or set them in the setup file before installing):
HTTPS_CERT_PATH=C:\HRPayroll\certs\hr.company.com-chain.pem
HTTPS_KEY_PATH=C:\HRPayroll\certs\hr.company.com-key.pem
HTTPS_PORT=443
APP_URL=https://hr.company.com
ALLOWED_ORIGIN=https://hr.company.com
  1. Allow port 443 in the firewall (New-NetFirewallRule -DisplayName "HR Payroll HTTPS" -Group "HR Payroll" -Direction Inbound -Protocol TCP -LocalPort 443 -Action Allow -Profile Domain,Private), then restart the HR Payroll Application service. Port 8080 now redirects to HTTPS.

Option 2 — Certificate from your company CA

Export it as a .pfx with its private key and set HTTPS_PFX_PATH (and HTTPS_PFX_PASSPHRASE). It is trusted on domain-joined PCs; phones need your CA certificate installed.

Option 3 — No HTTPS (LAN only)

Works for office PCs, but browsers mark the site "not secure", the kiosk camera may be refused in some browsers, and the mobile app cannot be used. Use only for a test.

Network and access from outside

  • Setup opens only the application port, for Domain and Private networks. The database port is never opened: it listens on localhost.
  • Kiosk PCs and office PCs reach the server on the LAN by its name or IP; all of them are allowed automatically.
  • From outside: preferably over your VPN. If you publish it to the internet, publish only HTTPS (443) through your firewall, with a valid certificate, keep Windows updated and require two-step verification for administrators.

Creating the CyberAP package from SQL Server

Because HR & Payroll runs on Windows, the Data Import page can read CyberAP straight from SQL Server: no script to run, no file to copy or upload. It only reads; CyberAP is never changed.

  1. Sign in as an administrator (or a user with the Data import permission) and open Data Import. The page is visible while OneNet has data import switched on.
  2. Press Create package from SQL Server. The SQL Server instances on this machine are suggested (for example .\SQLEXPRESS); another server can be typed as SERVER\INSTANCE or 10.0.0.5,1433.
  3. Choose SQL login and enter a login that can read CyberAP (see below), then press Connect and list databases. The database that contains CyberAP is marked with its number of employees.
  4. Optional: Attendance from a date (a top-up package after go-live) and Skip employee photos (smaller, faster test runs).
  5. Press Create package. Progress shows employees and attendance days as they are read; the full history takes several minutes and you may close the page. When it finishes, continue with Analyse (no changes) and Import.

A read-only SQL login is the simplest choice. Run once in SQL Server Management Studio (SQL Server must allow SQL Server and Windows Authentication mode):

CREATE LOGIN hr_import WITH PASSWORD = 'Choose-a-strong-password-1';
USE CyberAP;
CREATE USER hr_import FOR LOGIN hr_import;
ALTER ROLE db_datareader ADD MEMBER hr_import;

Windows (service account) sign-in connects as the account the application service runs as. When SQL Server is on the same machine that is NT AUTHORITY\NETWORK SERVICE; give it read access once:

CREATE LOGIN [NT AUTHORITY\NETWORK SERVICE] FROM WINDOWS;
USE CyberAP;
CREATE USER [NT AUTHORITY\NETWORK SERVICE] FOR LOGIN [NT AUTHORITY\NETWORK SERVICE];
ALTER ROLE db_datareader ADD MEMBER [NT AUTHORITY\NETWORK SERVICE];

For a SQL Server on another machine use the computer account instead, e.g. [DOMAIN\HEADOFFICE$]. The SQL password is used only for the export in progress; it is never saved or written to a log. Each package creation is recorded in the audit log (server, database and login name).

Database maintenance and speed

The embedded database looks after itself; nothing has to be done by hand.

WhatWhen and how
MemorySetup and every update size the database memory to this server (about 10% of RAM as cache when SQL Server runs here too, 20% otherwise). An update restarts the database service once when the size changes.
Quick optimisationEvery night after the backup: refreshes the statistics the database uses to plan queries and makes space from changed rows reusable. Safe while people work.
Deep optimisation (shrink)First Sunday of the month after the backup: rewrites every table compactly and gives disk space back. Each table is locked briefly (the attendance table can take a few minutes), which is why it runs at night.
By handData Backup → Database health & optimisation: size, largest tables, unused space, memory, and Quick optimise / Deep optimise (shrink) (deep takes a backup first). Results are listed there and in logs\backup.log.

Backups

  • The task HR Payroll Nightly Backup runs every night (default 01:30) as SYSTEM and writes an encrypted hr-payroll-<time>.dump.enc plus a manifest to C:\HRPayrollData\backups; the newest 14 are kept.
  • With BackupCopyTo the files are also copied to that folder or share. For a share, give the server's computer account (DOMAIN\SERVER01$) write access.
  • Run one by hand at any time: powershell -ExecutionPolicy Bypass -File C:\HRPayroll\tools\hrpayroll-backup.ps1.
  • The backups can only be restored with the BACKUP_ENCRYPTION_KEY from config\.env: keep that copy off the server.
  • Test a restore on a spare machine every few months.

Restoring a backup

powershell -ExecutionPolicy Bypass -File C:\HRPayroll\tools\hrpayroll-restore.ps1 ^
  -BackupFile C:\HRPayrollData\backups\hr-payroll-2026-11-07T20-00-00-000Z.dump.enc

It asks you to type RESTORE, takes a safety backup of the current database, stops the application, replaces the database with the backup, brings an older backup up to the installed version and starts the application again. Everything entered after the backup is lost.

Updating

  1. Extract the new package (same as for installing).
  2. As Administrator: powershell -ExecutionPolicy Bypass -File C:\Setup\HRPayroll-new\setup\Update-HRPayroll.ps1
  3. The update takes a safety backup, copies the new version beside the old one, applies the database changes, switches over, restarts and checks. If the new version does not answer, it switches back automatically.
  4. Old version folders in C:\HRPayroll\app can be deleted after a few weeks.

Licence and edition

The edition (Full or Lite) and the licence are managed by OneNet through the vendor console on the sign-in screen. OneNet can also switch the Data Import screen on or off there. No customer data is visible in the vendor console.

Security checklist

  • Copy of config\.env stored off the server.
  • HTTPS with a valid certificate before anyone uses the mobile app or works from outside.
  • Administrator password changed at first sign-in; two-step verification on for every administrator.
  • Nightly backup task enabled and a copy going to another machine; a test restore done.
  • Database port 5433 not opened in any firewall (it listens on localhost only).
  • Windows Update and antivirus active; exclusion for the database folder.
  • Data Import switched off after go-live (ask OneNet).

Uninstalling

powershell -ExecutionPolicy Bypass -File C:\HRPayroll\tools\Uninstall-HRPayroll.ps1

Removes the services, the backup task, the firewall rule and C:\HRPayroll, and keeps C:\HRPayrollData (database, documents, backups). Add -RemoveData and type DELETE ALL DATA to delete the data too.

Troubleshooting

ProblemCause and fix
Setup: "Run setup as Administrator"Right-click Setup.cmd → Run as administrator.
Setup: "Port 8080 is already in use"Another program uses it. Set AppPort to a free port (e.g. 8090) in the setup file.
Setup: "The package is incomplete"Extract the whole zip (not only Setup.cmd) and run it from the extracted folder.
Browser: site cannot be reachedCheck the status tool; check the firewall rule profile (Domain/Private) and that you use the right port.
"Request origin is not allowed"The address you typed is not in the allowed list. Add it to ALLOWED_ORIGINS in config\.env and restart the application.
HR Payroll Database does not startSee C:\HRPayrollData\logs\postgresql. Common: disk full, or antivirus locking database files.
HR Payroll Application stops again and againSee C:\HRPayrollData\logs\app. Common: a typing error in .env, or a certificate path that does not exist.
Backup failed (logs\backup.log)Disk full, or the share in BackupCopyTo not writable by the server's computer account.
Browser on another PC: page stays blank, console shows ERR_SSL_PROTOCOL_ERRORFixed in 2026.11.08: plain http:// addresses no longer tell browsers to switch to HTTPS. After updating, open the address in a private window once (or clear the site data) so the browser forgets the old instruction.
Signed in, but "Access Denied … (No Role)"Installations made before 2026.11.08 had no roles. Update: the server adds the standard roles when it starts.
Create package from SQL Server: "Login failed"Wrong login or password, or SQL Server allows Windows authentication only. Use the read-only login above, or the Windows (service account) option after granting access.
Create package from SQL Server: database not marked CyberAPThe login cannot open it (give it db_datareader), or it is not a CyberAP database.
HTTPS: browser warns about the certificateWrong name in the certificate, expired certificate (win-acme renewal task failed) or an internal CA not trusted on that device.
